    34. Development¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051. Commands below are drawn from pyproject.toml's actual configuration and Next Steps.md's "Reference: commands that are easy to forget" section — nothing here is invented tooling.

    34.1 Install¶

    cd exocomet-hunter
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

    requires-python = ">=3.11" (pyproject.toml); the README's own install instructions use python3.12 explicitly. The [dev] extra pulls in pytest, pytest-cov, pytest-benchmark, hypothesis, mypy, ruff, black, pre-commit, pandas-stubs, types-PyYAML. A separate [docs] extra (mkdocs-material, mkdocstrings[python]) exists for building documentation — G2 in Next Steps.md (a deployed MkDocs site) is PLANNED, not built; the dependency is declared but no mkdocs.yml or docs-site build has shipped.

    34.2 Console entry point¶

    [project.scripts]
exocomet = "exocomet.cli:main"

    Once installed (pip install -e .), the exocomet command is available directly:

    exocomet run "KIC 3542116" --mission Kepler
exocomet validate
exocomet inject --n 20

    See 35_code_reference/cli.md for the full subcommand reference.

    34.3 Run the pipeline directly (without the installed console script)¶

    from exocomet.io.download import fetch_light_curve
from exocomet.detrend.detrend import detrend_savgol
from exocomet.detect.comet_detector import AsymmetricDipDetector

lc = detrend_savgol(fetch_light_curve("KIC 3542116", mission="Kepler"))
for record in AsymmetricDipDetector().run(lc):
    if record.score.flagged:
        print(record.event.t_min, record.event.depth_ppm, record.score.delta_bic)

    (As given in README.md, "Use" section.)

    34.4 Test¶

    pytest tests/unit -q                     # 167 tests, ~4 s (measured 2026-09-16, see 27_testing.md)
pytest tests/integration -m network       # requires live MAST access
pytest --cov=exocomet tests/unit          # configured, never yet run — see 27_testing.md §27.3

    pyproject.toml's [tool.pytest.ini_options] defines network and slow custom markers; -m "not network" deselects network tests explicitly if needed (the default testpaths = ["tests"] with addopts = "-ra --strict-markers" means an undeclared marker is a hard error, not a silent typo).

    34.5 Lint and type-check¶

    34.7 Ingestion pipeline (production automation)¶

    python scripts/ingest.py                 # fetch -> extract -> detect -> results -> ledger, resumable
python scripts/build_local_db.py         # rebuild a disposable local.db view from ledger.jsonl (never committed)
python scripts/run_validation.py --offline   # synthetic validation-gate check, no network
python scripts/run_validation.py             # real validation gate against MAST

    34.8 GitHub Actions workflow management — needs the right gh account¶

    Per Next Steps.md's own "easy to forget" reference, verbatim, because the active local gh account (elpis-app) is not the account these repositories belong to (AJpro-merc) — see 41_troubleshooting.md for the full incident this workaround exists to route around:

    GH_TOKEN=$(gh auth token -u AJpro-merc) gh run list --workflow=survey.yml
GH_TOKEN=$(gh auth token -u AJpro-merc) gh workflow run survey.yml -f dry_run=true
GH_TOKEN=$(gh auth token -u AJpro-merc) gh workflow disable survey.yml

# git push already works inside the repo (local credential config set)
git push

    Three workflows exist in .github/workflows/ as of this commit: ingest.yml (hourly, active), train.yml (every 2h generation + weekly training, disabled pending the pre-squash-commit re-anchor described in 41_troubleshooting.md), survey.yml (daily, disabled pending A1/A2/A4 — all three of which are now done per Next Steps.md, so re-enabling is a live decision outstanding, not a code blocker).

    34.9 Ruff/mypy/pytest configuration reference (pyproject.toml, verbatim key settings)¶

    • [tool.ruff]: line-length = 100, target-version = "py311", rule sets E, W, F, I, N, D, UP, B, SIM, NPY, RUF selected; D105, D107, N803, N806 explicitly ignored (the latter two to allow the paper's own uppercase notation, e.g. A_dur); pydocstyle convention is numpy; tests/* and scripts/* get relaxed docstring requirements via per-file ignores.
    • [tool.mypy]: python_version = "3.11", strict = true, warn_unreachable = true, scoped to files = ["src/exocomet"] only (tests and scripts are not mypy-checked); third-party libraries without stubs (lightkurve, astroquery, astropy, scipy, matplotlib, pyarrow) have ignore_missing_imports = true.
    • [tool.coverage.run]/[tool.coverage.report]: source scoped to src/exocomet, branch coverage enabled, standard exclusion patterns for pragma: no cover, TYPE_CHECKING blocks, NotImplementedError, and @abstractmethod.
