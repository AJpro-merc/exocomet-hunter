    20. Validation¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051 (unmodified in the working tree's uncommitted diff). run_validation.py and the hold-out guard are IMPLEMENTED / TESTED (offline mode) / the epoch-recovery result quoted in §20.3 is VALIDATED against real MAST data per the README and research log 003, but was not re-run by this document's author — cited from source, not independently reproduced here.

    20.1 The six-event KIC 3542116 exam¶

    config/validation_targets.yaml transcribes six published dips for KIC 3542116 from Rappaport et al. (2018, MNRAS 474(2):1453, arXiv:1708.06069), explicitly "not inferred from our own detections... the validation gate is only meaningful if it compares against numbers that came from the literature":

    Dip t_min_bkjd depth_ppm note
    D140 139.98 491 shallow
    D742 742.45 524 shallow
    D793 792.78 679 shallow
    D992 991.95 1200 deep
    D1176 1175.62 1500 deep
    D1268 1268.10 1900 deep

    match_tolerance_days: 0.5 — deliberately far looser than the paper's own quoted epoch uncertainty (±0.02 d), because "our pipeline reports the flux minimum, which need not coincide exactly with the paper's fitted epoch" (config file comment, lines 10–12).

    A second target, KIC 11084727, is listed with expected_dip_count: 1 but dips: [] — confirmed by direct read of config/validation_targets.yaml line 55 as of this document: the epoch has not been transcribed from the paper. This matches docs/NEXT_STEPS.md's open item B5 exactly; it has not been filled in since (the file is unchanged from the state Next Steps describes — no working-tree diff touches this file).

    20.2 The hold-out guard¶

    EXCLUDED_HOLD_OUT_TARGETS (scripts/build_kepler_host_list.py line 26, verified by direct read of the current working-tree file):

    EXCLUDED_HOLD_OUT_TARGETS: frozenset[str] = frozenset({"KIC 3542116", "KIC 11084727"})

    This is the exact, real frozenset — both validation targets. It is enforced in three independent places, defense-in-depth style:

    1. KEPLER_HOST_STARS itself has a module-level assertion (lines 74–79): assert not (set(KEPLER_HOST_STARS) & EXCLUDED_HOLD_OUT_TARGETS) — a syntax error in the training-host list, not a runtime check, so it fails at import time if violated.
    2. scripts/ingest.py's get_target_list() (lines 105–151) re-imports and re-checks the same set against every target source, including the optional catalogue-expansion file — "defense in depth, so a future third target source cannot silently leak a validation star into generated data without a loud failure" (docstring, lines 122–124), raising AssertionError if any leak is found.
    3. KNOWN_BAD_HOSTS = frozenset({"KIC 1026032"}) is a separate set, for a different reason: KIC 1026032 has real Kepler data and was excluded because direct pipeline inspection found a strong (~8% deep, ~8.4-day period) real eclipsing-binary signal — not because it is a validation target. The five KIC IDs removed in the 2026-09-16 working-tree fix (13_detrending.md/11_pipeline.md §11.6) were removed from KEPLER_HOST_STARS outright, not added to KNOWN_BAD_HOSTS, because they have no observations at all.

    20.3 scripts/run_validation.py — the automated gate¶

    What it checks (module docstring, lines 12–20): only epoch recovery. For every dip in validation_targets.yaml, there must be a detected event whose flux minimum lies within match_tolerance_days of the published epoch. The flagged boolean is reported in the output table but deliberately does not decide pass/fail — quoting directly: "the flagging rule is a tunable policy that is expected to move, while 'the detector finds an event at this epoch' is the stable contract the published result rests on."

    Matching logic — match_dips(known, detections, tolerance_days) (lines 194–257): builds every (offset, known_index, detection_index) triple within tolerance, sorts by offset ascending, and greedily assigns nearest-first, with each known dip and each detection usable at most once (assigned/used_detections sets). This prevents one detected event from "recovering" two published epochs, and prevents a spurious extra detection from counting against the target — "spurious extra detections are not a failure of the recovery gate — missing a known dip is" (docstring, lines 204–205).

    Exit codes (exit_code(), lines 585–602): 0 if every known dip of every checked target was recovered; 1 if any known dip was missed, any target errored, or (with --strict) any target was skipped for lack of transcribed epochs; 2 if the run itself could not be carried out (bad config file). A target with dips=[] (i.e. KIC 11084727 today) is skipped, not passed — TargetResult.passed explicitly returns False for a skipped target: "a skipped target is explicitly not a pass: counting an untested star as green is exactly how a gate stops being a gate" (lines 286–294).

    Offline mode (--offline): builds a synthetic light curve with dips injected at exactly the published epochs (synthetic_light_curve(), lines 318–399, reusing tests/conftest.py's inject_asymmetric_dip/make_flat_light_curve fixtures) and runs the real detrend_savgol → AsymmetricDipDetector pipeline over it — no network access. --offline-drop-epoch BKJD deliberately omits one injected dip, which must make the gate fail, as the documented proof that the gate is actually capable of failing (rather than vacuously passing regardless of input).

    20.4 Real-data epoch recovery (as reported in the README, cited not re-run)¶

    The README (top-level, "Does it work?" section) states all six KIC 3542116 dips are recovered against real MAST data:

    Published (BKJD, ppm) Recovered (BKJD) Epoch error (d)
    139.98, 491 140.026 0.046
    742.45, 524 742.574 0.124
    792.78, 679 792.895 0.115
    991.95, 1200 991.979 0.029
    1175.62, 1500 1175.671 0.051
    1268.10, 1900 1268.284 0.184

    All six offsets are well within the configured 0.5-day match_tolerance_days. This table is consistent with, and is the origin of, the depth-ratio numbers analysed in research log 006 and 22_published_validation.md. This document did not independently re-run the live (--offline off) gate against MAST to reproduce these exact numbers; they are cited from the README and cross-checked for internal consistency against research log 006's depth table, which uses the same six epochs.

    20.5 What remains unautomated / open¶

    • KIC 11084727's missing epoch (§20.1) means the validation gate currently checks exactly one of its two configured targets in any real sense; the second is always skipped.
    • docs/NEXT_STEPS.md (working tree) lists, under B2, an unexplained event at BKJD 1064.245 (531 ppm) in KIC 3542116 not corresponding to any of the six published dips — explicitly flagged "do not call it a discovery," and not investigated further as of this document.
