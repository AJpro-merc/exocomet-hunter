    57. API / Interface Contracts¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051.

    All signatures below are transcribed directly from src/exocomet/core/interfaces.py and src/exocomet/core/types.py (line numbers refer to the files as of commit 01c2051).

    57.1 LightCurveSource (Protocol, runtime_checkable)¶

    @runtime_checkable
class LightCurveSource(Protocol):
    def fetch(self, target_id: str, mission: str) -> LightCurveData: ...

    Structural typing (Protocol + @runtime_checkable) — any object with a matching fetch method satisfies this interface without explicit inheritance. Real implementation: MastLightCurveSource in src/exocomet/io/download.py.

    Status: IMPLEMENTED (one real implementation exists).

    57.2 Detrender (Protocol, runtime_checkable)¶

    @runtime_checkable
class Detrender(Protocol):
    def detrend(self, lc: LightCurveData) -> LightCurveData: ...

    Real implementations: SavGolDetrender, SplineDetrender in src/exocomet/detrend/detrend.py (both are thin classes wrapping the module-level detrend_savgol/detrend_spline functions, which are what the rest of the codebase — cli.py, scripts/ingest.py — actually calls directly rather than going through these wrapper classes).

    Status: IMPLEMENTED (two real implementations).

    57.3 Vetter (Protocol, runtime_checkable)¶

    @runtime_checkable
class Vetter(Protocol):
    def vet(self, event: DipEvent, lc: LightCurveData) -> VettingResult: ...

    Real implementations: none. src/exocomet/vetting/ has no class satisfying this protocol. Every CandidateRecord.vetting field observed in real pipeline output (§45.5, §58) is None.

    Status: DEFINED, NOT IMPLEMENTED.

    57.4 Detector (abstract base class, not a Protocol)¶

    class Detector(ABC):
    name: str = "detector"

    @abstractmethod
    def detect(self, lc: LightCurveData) -> list[DipEvent]: ...

    @abstractmethod
    def score(self, event: DipEvent, lc: LightCurveData) -> EventScore: ...

    def run(self, lc: LightCurveData) -> list[CandidateRecord]:
        return [CandidateRecord(event=event, score=self.score(event, lc)) for event in self.detect(lc)]

    Unlike the other three interfaces, Detector is a real abc.ABC requiring subclassing (not structural typing), with a concrete run() method provided by the base class that composes detect() and score(). The docstring is explicit about why: "answers two questions... Splitting the two keeps the expensive statistical work off the path of the cheap first pass." Real implementation: AsymmetricDipDetector in src/exocomet/detect/comet_detector.py — the only Detector subclass in the codebase as of this commit. The module docstring states the planned second implementation (an anomalous-dimming/technosignature detector, Next Steps H4) is added "by implementing Detector... no orchestration code changes" — this claim is architecturally plausible given the interface design but is UNVERIFIED since no second Detector subclass has ever actually been written to test it.

    Status: IMPLEMENTED (one real subclass; the extensibility claim is a design intent, not yet exercised by a second real implementation).

    57.5 Data model contracts (core/types.py)¶

    All are frozen (@dataclass(frozen=True)) — immutable once constructed, so downstream code cannot silently mutate a shared LightCurveData or CandidateRecord.

    Type Fields Notes
    LightCurveData target_id: str, mission: str, time: FloatArray, flux: FloatArray, flux_err: FloatArray, meta: dict[str, Any] __post_init__ raises ValueError on length mismatch, empty arrays, or non-strictly-increasing time. Properties: n_points, cadence_days (median np.diff(time)), baseline_days. with_flux() returns a new instance with merged meta.
    EventWindow start_index: int, end_index: int, start_time: float, end_time: float Both index bounds inclusive. Properties: duration_days, n_points.
    SideFit duration_days, slope, slope_err, n_points, half_depth_time One ingress or egress side's linear fit.
    AsymmetryResult a_dur: float, a_slope: float, ingress: SideFit, egress: SideFit signs_agree property: np.sign(a_dur) == np.sign(a_slope) and a_dur != 0.0.
    DipEvent target_id, t_min, f_min, depth, window: EventWindow, asymmetry: AsymmetryResult \| None, unmeasurable_reason: str \| None depth_ppm = depth * 1e6. is_measurable = asymmetry is not None.
    ModelFit name, params: dict[str, float], chi2, n_params, n_points, converged bic property returns inf if not converged or n_points <= 0.
    ModelComparison symmetric: ModelFit, comet: ModelFit, delta_bic_threshold: float = 10.0 delta_bic = symmetric.bic - comet.bic (positive favors comet); favors_comet = delta_bic > delta_bic_threshold; tau_over_sigma reads comet.params["egress_tau"] / comet.params["ingress_width"], returns nan if either is non-finite or sigma <= 0.
    EventScore a_dur_sigma, significance, signs_agree, flagged, periodic: bool = False, period_days: float \| None = None, model: ModelComparison \| None = None delta_bic/tau_over_sigma properties delegate to model, nan if model is None.
    VettingStatus str, Enum: CANDIDATE, ECLIPSING_BINARY, FLARE, ARTIFACT, KNOWN_VARIABLE, UNRESOLVED Vocabulary defined; no code constructs any value other than implicitly via None (i.e., not constructed at all) as of this commit.
    VettingResult status: VettingStatus, reasons: tuple[str, ...] = (), catalog_matches: dict[str, str] is_candidate property: status is VettingStatus.CANDIDATE. No instance of this type is ever constructed by pipeline code as of this commit (§45.5).
    CandidateRecord event: DipEvent, score: EventScore, vetting: VettingResult \| None = None to_row() flattens to a dict of 19 fields for tabular output (used by cli.py, scripts/ingest.py, scripts/build_local_db.py).

    Command Args Exit codes
