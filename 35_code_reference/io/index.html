    35. Code Reference — exocomet.io¶

    35.1 exocomet.io.download¶

    fetch_light_curve¶

    Source: src/exocomet/io/download.py:285-435

    def fetch_light_curve(
    target_id: str,
    mission: str = "Kepler",
    cadence: str = "long",
    author: str | None = None,
    exptime: int | None = None,
    cache_dir: Path | str = DEFAULT_CACHE_DIR,          # "data/raw"
    discard_after_read: bool = False,
    quality_bitmask: str = "default",
    search_timeout: float = DEFAULT_SEARCH_TIMEOUT,      # 60.0 s
    download_timeout: float = DEFAULT_DOWNLOAD_TIMEOUT,  # 300.0 s
    max_attempts: int = DEFAULT_MAX_ATTEMPTS,            # 3
    retry_backoff: float = DEFAULT_RETRY_BACKOFF,        # 5.0 s
) -> LightCurveData

    Behaviour. Downloads, stitches, and normalises all available photometry for one target via lightkurve.search_lightcurve(...).download_all(...).stitch(). For TESS, defaults author to "SPOC" and exptime to 120 when not supplied; for Kepler/K2, defaults author to "Kepler" and ignores exptime (uses cadence instead). Normalises flux by its median (flux / median, flux_err / median); drops non-finite and duplicate-timestamp cadences.

    Returns. LightCurveData with meta populated with n_dropped_nonfinite, n_dropped_duplicate_timestamp, median_raw_flux, source="MAST", n_products, author, exptime, sectors_or_quarters.

    Raises. - FileNotFoundError — the archive returns zero products for this target/mission/author/exptime combination. - MastTimeoutError (subclasses TimeoutError) — the catalogue query or bulk download exceeds its wall-clock budget on every attempt. - ValueError — raised inside _to_light_curve_data if the median flux is non-positive or non-finite ("cannot normalise").

    External dependencies. lightkurve (imported lazily inside the function body — not at module load — so importing exocomet.io.download itself has no network/heavy-import cost), astroquery.mast (configured via _configure_astroquery, best-effort).

    Failure modes and mitigations, as documented in source: - A stalled MAST socket with no deadline: mitigated by running each network call on a daemon thread and abandoning the wait (not the thread) after its timeout (_call_with_timeout). Documented residual limitation: "the orphaned thread keeps holding its socket until astroquery's own ASTROQUERY_TIMEOUT trips" — the bound is on caller wait time, not on freeing the underlying resource. - A truncated FITS file left by an interrupted download poisoning subsequent retries (found 2026-09-15): _call_with_retries accepts an optional cleanup callback, invoked after a failed attempt and before the next; the download_all call site passes cleanup=lambda: _discard_cached(cache, target_id) specifically to wipe the poisoned cache between attempts. - discard_after_read=True deletes the entire mastDownload tree under cache_dir after extraction (see _discard_cached below) — correct only when targets are processed one at a time (true of every current caller).

    iter_light_curves¶

    Source: src/exocomet/io/download.py:468-543

    def iter_light_curves(
    target_ids: list[str],
    mission: str = "Kepler",
    cadence: str = "long",
    author: str | None = None,
    exptime: int | None = None,
    cache_dir: Path | str = DEFAULT_CACHE_DIR,
    discard_after_read: bool = True,
    skip_errors: bool = True,
    per_target_timeout: float | None = DEFAULT_TARGET_BUDGET,  # 900.0 s
    search_timeout: float = DEFAULT_SEARCH_TIMEOUT,
    download_timeout: float = DEFAULT_DOWNLOAD_TIMEOUT,
    max_attempts: int = DEFAULT_MAX_ATTEMPTS,
    retry_backoff: float = DEFAULT_RETRY_BACKOFF,
) -> Iterator[LightCurveData]

    Behaviour. Yields light curves one at a time via fetch_light_curve, discarding each target's cache after it is consumed (default discard_after_read=True, unlike fetch_light_curve's own default of False) — "the memory- and disk-safe way to process a large target list: at any moment only one star's photometry exists locally." Wraps each fetch in an outer per_target_timeout (default 900 s) covering the whole of fetch_light_curve including its own internal retries — this is what stops one hung star from stalling an entire batch, distinct from the per-call timeouts inside fetch_light_curve itself.

    Raises. Nothing propagates for an individual target failure when skip_errors=True (default) — the exception is logged (logger.warning) and the target skipped. When skip_errors=False, the first failure propagates and stops iteration.

    Documented failure mode. A target abandoned at per_target_timeout leaves its worker thread running in the background; if that thread later completes with discard_after_read=True, it can wipe the shared mastDownload tree out from under whatever target is being processed next. Docstring: "The blast radius is a redundant re-download rather than corrupt science" — not data corruption, but a real, acknowledged race.

    class MastLightCurveSource:

    MastTimeoutError¶

    Source: src/exocomet/io/download.py:85-93

    class MastTimeoutError(TimeoutError): ...
    Raised by _call_with_timeout when a wrapped call exceeds its budget. Subclasses TimeoutError specifically so existing except OSError/except Exception handlers — including iter_light_curves's skip_errors path — keep working unchanged without special-casing it.

    Internal helpers (not exported, documented here because they carry real behaviour a caller should know about)¶

    • _configure_astroquery(timeout=120.0, pagesize=5000) — best-effort; pins astroquery.mast's connection timeout and page size to bounded values. Wrapped in a bare except Exception because the private attributes it touches (_portal_api_connection, _service_api_connection) have shifted name across astroquery releases; failing to tune them must never fail a download. Source: src/exocomet/io/download.py:94-125
    • _call_with_timeout(func, timeout, description) — runs func on a daemon thread, joins with a timeout, raises MastTimeoutError if still alive. Daemon (not ThreadPoolExecutor) specifically because a stalled socket cannot be cancelled from outside, and a non-daemon executor would join its workers at interpreter shutdown, turning a bounded call back into a hang. Source: src/exocomet/io/download.py:126-140
    • _call_with_retries(func, timeout, description, max_attempts, backoff, cleanup=None) — bounded retry with exponential backoff (backoff * 2**(attempt-1)); cleanup runs between failed attempts, never after the last exhausted one. Source: src/exocomet/io/download.py:161-209
    • _discard_cached(cache, target_id) — deletes the whole cache / "mastDownload" tree. target_id is accepted but unused for matching (kept for logging only) — see 07_data_architecture.md §7.3 for why name-based matching was tried and abandoned. Source: src/exocomet/io/download.py:436-467
    • _to_light_curve_data(lc, target_id, mission, extra_meta=None) — converts a stitched lightkurve object to LightCurveData; drops non-finite and duplicate-timestamp cadences; raises ValueError on non-positive/non-finite median flux. Source: src/exocomet/io/download.py:210-261
    • _extract_sectors_or_quarters(search) — best-effort; wrapped in a bare except Exception returning [], since this is provenance-only metadata never worth failing a download over. Source: src/exocomet/io/download.py:262-284

    35.2 exocomet.io.extract¶

    sanitize_target_id¶

    Source: src/exocomet/io/extract.py:53-70

    def sanitize_target_id(target_id: str) -> str
    Replaces spaces, /, and \ with underscores. Not guaranteed reversible (documented); the original string is always recovered from file metadata instead, never from the filename.

    extract_path¶

    Source: src/exocomet/io/extract.py:71-81

    def extract_path(base_dir: Path | str, mission: str, target_id: str) -> Path
    Returns <base_dir>/extract/<mission>/<sanitize_target_id(target_id)>.parquet. No exceptions raised; pure path computation.

    save_extract¶

    Source: src/exocomet/io/extract.py:82-127

    def save_extract(data: LightCurveData, path: Path) -> None
    Behaviour. Writes data.time/data.flux/data.flux_err as parquet columns; embeds target_id, mission, and JSON-encoded meta as parquet schema metadata (keys exocomet.target_id, exocomet.mission, exocomet.meta_json). Writes to a temp file in the same directory via tempfile.mkstemp, then os.replaces it into place — atomic on POSIX.

    Raises. Propagates any exception from pq.write_table or os.replace (e.g. OSError on a full disk); in every such case the temp file is removed (tmp_path.unlink(missing_ok=True)) before re-raising, via a bare except BaseException — so a failed write never leaves a stray .tmp file behind, but note this also swallows KeyboardInterrupt/SystemExit into the cleanup path before re-raising them.

    External dependencies. pyarrow/pyarrow.parquet (used directly, not via pandas — see 08_storage.md §8.1 for why).

    load_extract¶

    Source: src/exocomet/io/extract.py:128-153

    def load_extract(path: Path) -> LightCurveData
    Behaviour. Reads the parquet file, reconstructs target_id/mission/meta from schema metadata (empty string/{} if a key is missing — no exception raised for a file missing this project's own metadata keys, e.g. a parquet file from another source), and time/flux/flux_err from columns via to_numpy(zero_copy_only=False).

    Raises. Propagates pyarrow's own exceptions for a missing or malformed file (e.g. FileNotFoundError, pyarrow.lib.ArrowInvalid); propagates LightCurveData.__post_init__'s ValueError if the reconstructed arrays are empty, mismatched in length, or not strictly time-increasing.

    append_entry¶

    Source: src/exocomet/io/ledger.py:89-134

    def append_entry(ledger_path: Path, entry: LedgerEntry) -> None
    Behaviour. Serialises entry via dataclasses.asdict + json.dumps, writes it as one line in append ("a") mode, then flush()s and os.fsync()s the file descriptor. Before writing, checks (in binary mode) whether the file's last byte is \n; if not, writes a leading \n first, to avoid concatenating onto a torn previous write.

    Raises. Propagates OSError from file operations (e.g. disk full, permission denied). No validation of entry's field values beyond what the frozen dataclass's type hints imply at construction time (not enforced at runtime by the dataclass itself).

    Side effects. Creates ledger_path.parent if missing (mkdir(parents=True, exist_ok=True)).

    read_ledger¶

    Source: src/exocomet/io/ledger.py:135-164

    def read_ledger(ledger_path: Path) -> list[LedgerEntry]
    Returns [] if the file does not exist (not an exception). Skips and logs (logger.warning) any line that fails json.JSONDecodeError or TypeError (e.g. a torn trailing write, or a line with unexpected fields) — does not raise for a corrupt line.

    latest_entries¶

    Source: src/exocomet/io/ledger.py:165-179

    def latest_entries(entries: list[LedgerEntry]) -> dict[tuple[str, str], LedgerEntry]
    Pure reduction assuming entries is in chronological (append) order; last entry per (target_id, mission) wins. No exceptions raised.

    get_status¶

    Source: src/exocomet/io/ledger.py:180-196

    def get_status(ledger_path: Path, target_id: str, mission: str) -> Literal["done", "pending"]
    Reads the full ledger and returns "done" iff the latest entry for the key has status == "success"; everything else (never attempted, or most recent attempt failed) is "pending".

    next_targets¶

    Source: src/exocomet/io/ledger.py:197-241

    def next_targets(
    ledger_path: Path,
    all_targets: list[str],
    mission: str,
    max_attempts: int = 3,
) -> list[str]
    Behaviour. Returns targets from all_targets that are either never-attempted or whose latest entry is status="failed" with attempt < max_attempts. Ordering: never-attempted targets first (in the order given in all_targets), then retriable failures oldest-failure-first by timestamp_utc — so a single flaky target retried repeatedly cannot starve an older failure of a retry slot. A target whose latest entry is status="success", or that has exhausted max_attempts, is excluded entirely.

    Raises. None beyond whatever read_ledger raises (i.e., effectively none — corrupt lines are skipped, not raised).
