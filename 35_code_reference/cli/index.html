    35. Code Reference — exocomet.cli¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051. IMPLEMENTED. Cross-reference: 34_development.md for install/usage context.

    Module: src/exocomet/cli.py. Declared in pyproject.toml as exocomet = "exocomet.cli:main". Every heavyweight or network-touching import (numpy, yaml, the detrend/detect/io modules) is deferred inside the function that needs it — this is deliberate, so exocomet --help returns instantly with zero network access and no science-stack import cost, mirroring the lazy import lightkurve pattern in io/download.py. __all__ = build_parser, main.

    build_parser() -> argparse.ArgumentParser¶

    Source: src/exocomet/cli.py:256-308

    Constructs the full parser, separated from main() specifically so tests can exercise argument parsing without executing a pipeline or touching the network (tests/unit/test_cli.py). Top-level flags: --version (prints _version_string()), -v/--verbose (INFO-level logging). Subcommands, via add_subparsers(dest="command", metavar="{run,validate,inject}"):

    run subcommand → cmd_run(args) -> int¶

    Source: src/exocomet/cli.py:117-148

    Arguments: target (positional, e.g. "KIC 3542116"), --mission {Kepler,TESS} (default Kepler), --config PATH (YAML overrides), --all-events (print every event, not just flagged), --no-detrend (skip Savitzky-Golay detrending), --out PATH (also write every event as JSON Lines via CandidateRecord.to_row()).

    Behavior: fetches and (unless --no-detrend) detrends the target via _prepare_light_curve(), runs AsymmetricDipDetector(config).run(lc), prints a summary line and one formatted line per shown event (_format_record), and optionally writes every record (not just shown ones) to --out as JSON Lines with default=str for non-JSON-native types. Returns 0 always (no failure path defined beyond the shared exception handler in main()).

    validate subcommand → cmd_validate(args) -> int¶

    Source: src/exocomet/cli.py:149-210

    Arguments: --targets PATH (default config/validation_targets.yaml), --config PATH.

    Behavior: the validation gate. Loads the YAML spec, and for each target with at least one transcribed dip, fetches+detrends+detects, then for each published dip finds the highest-significance match within match_tolerance_days (default 0.5 d from the YAML, or the spec's own value). Prints PASS/MISS/ERROR/SKIP per dip — SKIP specifically for a target with dips: [] (KIC 11084727, per Next Steps B5 — the docstring is explicit that "counting it as a pass would make the gate a lie, and failing on it would block on a missing number"). Returns 0 only if n_expected > 0 and every expected dip was recovered; 1 otherwise (including the case of zero expected dips at all, which prevents a vacuously-true pass).

    inject subcommand → cmd_inject(args) -> int¶

    Source: src/exocomet/cli.py:211-255

    Arguments: --n (injections per depth, default 20), --depths (fractional depths to sweep; defaults to DEFAULT_INJECTION_DEPTHS = (2e-4, 5e-4, 1e-3, 2e-3, 5e-3), chosen to bracket the published KIC 3542116 dip range of 491–1900 ppm on both sides), --ingress/--egress (durations in days, defaults 0.1/0.5), --target (inject into real photometry for this star; omit for a synthetic host), --mission, --n-points/--noise (synthetic-host parameters, used only without --target), --config.

    Behavior: measures detection completeness via calibration.injection.run_injection_recovery, printing a per-depth table of raw-detection and flagged-detection completeness, overall flagged completeness, and the 50%-detection-depth floor (or "not reached by any tested depth" if none). Without --target, builds a flat noise-only synthetic host via the private _synthetic_light_curve() helper (Kepler long-cadence sampling, cadence_days = 0.02043) — the docstring is explicit that real photometry via --target is preferable "because real systematics are then part of the test," and the synthetic path exists only so the command remains runnable and reviewable offline.

    _load_config(path) -> PipelineConfig (private)¶

    Source: src/exocomet/cli.py:52-58

    PipelineConfig.from_yaml(path) if a path is given, else the built-in PipelineConfig() defaults.

    _prepare_light_curve(target_id, mission, config, detrend=True) -> LightCurveData (private)¶

    Source: src/exocomet/cli.py:59-73

    Shared fetch-then-detrend sequence: fetch_light_curve(target_id, mission=mission, discard_after_read=True) then detrend_savgol(lc, config.detrend) unless detrend=False. Identical in structure to the sequence used by scripts/monitor_new_data.py and scripts/train_classifier.py — the CLI does not duplicate pipeline logic, it wires together the same functions those scripts call directly.

    _format_record(record) -> str (private)¶

    Source: src/exocomet/cli.py:74-87

    Renders one CandidateRecord as a single aligned console line: FLAG/blank marker, t_min, depth (ppm), dur (days), a_dur (or n/a if unmeasurable), sig (significance), dBIC, tau/sigma — all fixed-width formatted for column alignment across many printed rows.

    _synthetic_light_curve(n_points, noise_sigma, seed) -> LightCurveData (private)¶

    Source: src/exocomet/cli.py:88-116

    Builds a flat, Gaussian-noise-only LightCurveData at Kepler long-cadence spacing, used only by cmd_inject when --target is omitted. meta carries synthetic=True and noise_sigma.

    _version_string() -> str (private)¶

    Source: src/exocomet/cli.py:309-318

    Returns f"exocomet-hunter {version('exocomet-hunter')}" via importlib.metadata.version, falling back to "exocomet-hunter (not installed)" on PackageNotFoundError — lets --version work from an editable/source checkout as well as an installed wheel.

    main(argv=None) -> int¶

    Source: src/exocomet/cli.py:319-353

    Parses arguments, prints help and returns 2 if no subcommand was given, configures logging (INFO if -v, else WARNING), then dispatches to the subcommand's func. Exit codes: 0 success, 1 a failed run (missed validation dip, unavailable target, malformed config — anything raising inside a subcommand handler), 2 usage error (no subcommand), 130 on KeyboardInterrupt. All exceptions besides KeyboardInterrupt are caught, logged at DEBUG with a full traceback (exc_info=True), and reported to the user as a single error: {exc} line on stderr — the CLI never lets a raw traceback reach an end user's terminal.
