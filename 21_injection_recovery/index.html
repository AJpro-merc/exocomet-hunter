    21. Injection and Recovery¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051 (this module is unmodified in the working tree's uncommitted diff). Functions IMPLEMENTED / TESTED. The specific completeness numbers quoted in the README are UNVERIFIED as current — see §21.4 for why.

    21.1 Module and rationale¶

    src/exocomet/calibration/injection.py. Its docstring states the method plainly: "A detection count on its own is close to meaningless. 'I found three events' only becomes a scientific statement once paired with 'and I would have found 90% of events like these, but only 20% of shallower ones.'" Injections go into real photometry wherever possible so genuine systematics, gaps, and stellar variability are part of the test.

    21.2 Public functions, exact signatures¶

    • inject_comet_transit(time, flux, t0, depth, ingress_duration, egress_duration) -> FloatArray (lines 46–79) — injects one piecewise-linear comet-shaped transit: a linear ramp down over ingress_duration days reaching t0, then a linear ramp back up over egress_duration days. The docstring is explicit that this is a deliberate mismatch against the Gaussian/exponential profile fitted by detect/model_comparison.py: "injecting exactly the model being fitted would flatter the pipeline, whereas a different shape tests whether it recovers events it was not tuned for." egress_duration > ingress_duration is the comet-like configuration.
    • inject_flare(time, flux, t0, amplitude, rise_duration, decay_duration) -> FloatArray (lines 82–117) — injects a stellar-flare-shaped brightening (positive flux excursion): linear rise over rise_duration, then exponential decay with e-folding time decay_duration. Explicitly framed as a "Next Steps D1 false-positive lookalike" — "the sign-flipped opposite of a comet transit," meant to test whether the detector or a future classifier can be confused by the most common real non-comet asymmetric excursion in stellar photometry.
    • inject_starspot_modulation(time, flux, period_days, amplitude, phase=0.0) -> FloatArray (lines 120–145) — adds a sinusoidal modulation (amplitude * sin(2π t / period_days + phase)) to the whole light curve, unlike the other two injectors which are localised to one event. Docstring cites a Next Steps D1 parameter range: period 0.5–30 d, amplitude 100–5000 ppm (1e-4–5e-3 fractional).
    • run_injection_recovery(lc, detector, depths, ingress_duration=0.1, egress_duration=0.5, n_per_depth=20, match_tolerance_days=0.5, config=None, rng=None) -> RecoveryGrid (lines 218–303) — the sweep driver.

    21.3 run_injection_recovery mechanics¶

    For each depth in depths, n_per_depth injections are placed at a uniformly random epoch t0 drawn from [lc.time[0] + pad, lc.time[-1] - pad], where pad = cfg.candidates.edge_margin_days + egress_duration + ingress_duration — kept clear of both the edge-detection guard (14_candidate_detection.md) and the injected event's own full width. Raises ValueError if the light curve is too short to host an injection clear of its edges. The unmodified detector.run(injected) is called on each injected copy; a detected event counts as a match for that injection only if its t_min is within match_tolerance_days of the injected t0, and among matches the one with highest score.significance is kept as best.

    Per injection, InjectionResult (lines 148–165, frozen) records: t0, depth, ingress_duration, egress_duration, detected (best is not None), flagged (best is not None and best.score.flagged), recovered_t0, recovered_a_dur, delta_bic (nan if not detected).

    RecoveryGrid (lines 168–215, frozen) aggregates: completeness(flagged_only=True) — overall recovery fraction, counting an injection as recovered only if both detected and flagged when flagged_only=True (the default), or merely detected when False; completeness_by_depth(flagged_only=True) — the same fraction grouped by injected depth; detection_floor(target_completeness=0.5) — the shallowest tested depth reaching the target completeness, or None if no tested depth reached it.

    Important interaction with the A4 fix (16_statistics.md): completeness() with its default flagged_only=True depends directly on EventScore.flagged, which is computed by the exact delta_bic/tau_over_sigma rule described in 16_statistics.md. Any recomputation of completeness numbers must therefore be re-run after A4, not reused from before it — see §21.4.

    21.4 The README's stated numbers, and why they are marked UNVERIFIED here¶

    The repository README states, in its "Does it work?" section:

    injecting 200 synthetic comets into real-noise photometry gives a 50% detection floor near 750 ppm and 100% recovery above 1000 ppm

    This is the only recorded injection-recovery result found anywhere in the repository — no results/ file, no script output log, and no research-log entry recording a RecoveryGrid run with n=200 injections was found during this review (searched scripts/, docs/research_log/, and results/ for the figures "200," "750," "1000" in this context — the only hits for "750" elsewhere in the codebase are the unrelated DEPTH_GRID_PPM constant in scripts/generate_training_labels.py, a different script used for classifier-training-label generation, not injection-recovery characterisation).

    Why this is flagged UNVERIFIED rather than reported as current fact:

    1. git log -1 --format=%cd README.md dates the README's current content to 2026-09-15 20:28, committed as part of the same commit (afa4bb2) that landed the A4 flagging-rule fix. It cannot be determined from the repository alone whether these specific 200/750/1000 numbers were generated before or after A4 changed what flagged (and therefore completeness(flagged_only=True)) means for any given event — the README prose was not necessarily regenerated alongside the code change that would invalidate its own completeness claim.
    2. Research log 003 (§ predates A4) documents that the pre-A4 flagging rule was proven to admit false positives (reversed-direction dips) that the A4 rule excludes, and research log 007 documents that A4 itself changed which injected events would register as flagged versus merely detected. A completeness curve computed under the old rule is not the same measurement as one computed under the current rule, even on identical injected data — the old rule's admitted false positives would have inflated apparent completeness for real comet-shaped injections that happened to also pass the old (sign-blind) test, in ways not reproducible under the current two-condition rule.
    3. No n_per_depth=200-equivalent driver script or notebook was found in the repo (run_injection_recovery's own parameter is n_per_depth, i.e. injections per depth, not total — "200 synthetic comets" as a total count implies either a small number of depths or a different invocation than a literal reading of the function signature's default of n_per_depth=20; this discrepancy could not be resolved by reading the source alone).

    Conclusion for this document: the 50%-at-750-ppm / 100%-above-1000-ppm claim is recorded here as the project's own stated (README) result, dated 2026-09-15, but its provenance (exact invocation, whether pre- or post-A4) could not be independently verified from the repository as it stands. It should be treated as UNVERIFIED / possibly stale pending a fresh, logged run_injection_recovery run against the current (post-A4) code, ideally with its invocation and raw RecoveryGrid output saved to docs/research_log/ in the style of logs 003/006/007, matching this project's own stated evidentiary standard for every other numeric claim in this specification batch.

    21.5 Depth grid used elsewhere (distinct tool, worth not conflating)¶

    scripts/generate_training_labels.py's DEPTH_GRID_PPM = (200, 300, 500, 750, 1000, 1500, 2000, 3000) (line 76) is a classifier-training-label generation depth sweep, not an injection-recovery-characterisation sweep, and is a different script from anything in calibration/injection.py. It shares the value 750 with the README's quoted floor, which may or may not be coincidental — this document does not assert a connection between the two beyond noting both exist.
