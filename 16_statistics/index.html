    16. Statistics and the Flagging Rule¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051 (this module is unmodified in the working tree's uncommitted diff — the A4 fix described here is already committed). IMPLEMENTED / TESTED. This is the most safety-critical section of the whole specification batch: an earlier version of this rule was proven to generate false positives, and the fix that replaced it surfaced a second, independent finding about what the replacement statistics can and cannot do.

    16.1 The rule as it exists today¶

    src/exocomet/detect/scoring.py, score_event(), lines 160–165:

    flagged = bool(
    np.isfinite(delta_bic)
    and np.isfinite(tau_over_sigma)
    and delta_bic > cfg.delta_bic_threshold
    and tau_over_sigma > cfg.tau_over_sigma_threshold
)

    where delta_bic = model.delta_bic and tau_over_sigma = model.tau_over_sigma (both ModelComparison properties, core/types.py — see 15_model_fitting.md), and cfg is a ScoringConfig. Both thresholds are config-driven, not hardcoded: ScoringConfig.delta_bic_threshold = 10.0 and ScoringConfig.tau_over_sigma_threshold = 1.0 (core/config.py lines 105, 109; mirrored in config/thresholds.yaml lines 70–71).

    Both statistics are nan when the model fit is missing or degenerate (compare_models returned None, or a fit did not converge), and a nan comparison is False in Python/NumPy — so an unfittable event fails closed: it is never flagged, regardless of any other property, rather than defaulting to flagged or raising.

    The EventScore returned also reports, but does not use to decide: a_dur_sigma (bootstrap uncertainty on the contour-based duration asymmetry), significance (|a_dur| / a_dur_sigma), and signs_agree (whether the two contour-based asymmetry metrics point the same direction). These remain in CandidateRecord.to_row() as output columns (core/types.py lines 327–349) for downstream inspection and for use as classifier features (calibration/features.py), but play no role in flagged.

    16.2 What this rule replaced, and why it had to change (A4 / research log 003)¶

    The rule this replaced was, in the code's own words (research log 007, quoting the pre-fix line):

    flagged = abs(a_dur) / sigma >= 3.0

    a_dur is the contour-based duration asymmetry from detect/asymmetry.py, measured at the half-depth crossing (AsymmetryConfig.half_depth_fraction = 0.5) on each side of the dip. Research log 003 proved this specific measurement can carry the wrong sign even for a genuine, unambiguously trailing-tail comet event: for a comet profile with Gaussian ingress width σ and exponential egress timescale τ, the half-depth crossing times are T_ingress(0.5) = 1.177σ and T_egress(0.5) = 0.693τ. Setting these equal shows the sign of a_dur at half-depth flips at τ/σ ≈ 1.70 — so any real comet with 1 < τ/σ < 1.70 (an unambiguously longer, slower-clearing tail by the physical τ/σ measure) produces a negative half-depth a_dur, i.e. reads as "faster egress than ingress," the opposite of the physical truth. Measured on the six published KIC 3542116 dips, four of six showed this exact sign flip despite every one of them having a real, independently-fitted τ/σ > 1 for at least some contour depths.

    Because the old rule used abs(a_dur), it was blind to this sign problem in the worst possible way: it would flag a dip as comet-like regardless of which direction it was lopsided in, as long as the magnitude was large enough. A dip with a slow ingress and a fast egress — the physically backwards direction for a trailing dust tail (imagine a leading-tail geometry with no trailing tail, or simply a mirror-imaged noise artifact) — produces a large |a_dur| exactly as the true comet does, and was flagged as a candidate. The old unit test test_reversed_asymmetry_is_flagged_with_the_opposite_sign asserted this behaviour was the expected, correct output — i.e. the test suite itself encoded the bug as a requirement until A4 inverted it.

    16.3 The A4 fix¶

    flagged = delta_bic > cfg.delta_bic_threshold and tau_over_sigma > cfg.tau_over_sigma_threshold — both quantities derived from the whole fitted comet profile (detect/model_comparison.py), not from a single contour level. Both thresholds moved into ScoringConfig/config/thresholds.yaml rather than being hardcoded. ModelComparison.favors_comet's own delta_bic > 10.0 was also made to read the same configured threshold, "so the ranking metric and the flagging rule cannot drift apart" (research log 007). The old unit test was renamed test_reversed_asymmetry_is_not_flagged with its assertion inverted; a companion test confirms significance is still populated for reversed events, so the sign information remains available as a reported feature even though it no longer gates anything.

    16.4 The second finding: ΔBIC alone is direction-blind (research log 007)¶

    While verifying the A4 fix, a synthetic mirror-image test was constructed: two events with identical depth, identical noise, identical total duration — one a genuine trailing-tail comet profile, the other the exact time-reversal of it (a leading tail: slow ingress, fast egress). The measured statistics (research log 007, the table is reproduced here exactly as recorded):

    Trailing tail (comet-like) Leading tail (time-reversed)
    ingress / egress 2.4 h / 12.0 h 12.0 h / 2.4 h
    $A_{dur}$ +0.57 −0.58
    τ/σ 4.15 0.23
    ΔBIC 151 201
    flagged under the A4 rule yes no

    The unexpected result: the reversed, physically backwards event scores a higher ΔBIC than the real comet — 201 against 151. The reason, stated directly in the research log: "ΔBIC compares a comet model against a symmetric model. It answers 'is this profile asymmetric?' — not 'is this profile asymmetric in the direction a dust tail produces?'" A mirror-image event is exactly as asymmetric as the original, so the comet model beats the symmetric model just as decisively either way; the small 201-vs-151 difference reflects noise-realisation details of this particular fit, not a real preference for one direction over the other. τ/σ is the only one of these statistics that encodes direction at all — 4.15 versus 0.23, a factor of eighteen, cleanly split across the threshold of 1.0.

    16.5 Why the two-condition rule is load-bearing, not redundant¶

    Quoting research log 007 directly, because this is the load-bearing conclusion of the whole finding and must not be paraphrased into something weaker:

    Neither is sufficient alone. ... Do not "simplify" this rule by dropping the τ/σ condition. It looks redundant next to a ΔBIC of 151 and is not. Removing it restores precisely the false-positive generator that A4 was opened to remove, and the resulting failure would be silent: the pipeline would keep recovering the six published dips (they are genuine trailing-tail events and pass either way) while also admitting every backwards event it encounters. Recovery of known events would not catch it.

    Restated plainly: ΔBIC > threshold establishes that there is a real asymmetric event (as opposed to a symmetric dip or noise). τ/σ > threshold establishes that the asymmetry points the physically correct direction (a trailing, slowly-clearing tail, rather than the reverse). A rule using only ΔBIC recreates the exact class of false positive that the pre-A4 abs(a_dur) rule generated — a reversed event with a strong, merely-not-symmetric profile — because ΔBIC has no way to distinguish "asymmetric the right way" from "asymmetric the wrong way." A rule using only τ/σ, conversely, has no mechanism for rejecting a genuinely symmetric or noise-dominated event as insufficiently comet-shaped in the first place; ΔBIC is what establishes that a comet-shaped fit is warranted over the null (symmetric) model at all.

    16.6 Terminology discipline¶

    Per project-wide convention (also stated in 00_document_control.md §0.4), this document never uses "confirmed" for a flagged=True event. A flagged event is a "candidate," "candidate event," "exocomet-like morphology," or "candidate consistent with an exocomet interpretation" — the flagging rule described here is a statistical shape test, not a confirmation of a physical exocomet, and every known instance of this pipeline's own history (research logs 003 and 007) shows the shape test getting past epoch-recovery validation while carrying a real, previously-undetected defect.
