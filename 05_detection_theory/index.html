    5. Detection Theory¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051. IMPLEMENTED and TESTED against the KIC 3542116 validation set unless noted otherwise.

    5.1 Planetary transit vs. exocomet transit: the discrimination problem¶

    As established in section 4, a planetary transit is symmetric and strictly periodic; an exocomet transit is asymmetric (fast fade, slow recovery) and not periodic on any observable timescale. Section 5 covers how this codebase turns that qualitative distinction into a quantitative, testable decision rule — and documents two real, project-specific findings (research logs 003 and 007) about how that rule can fail in non-obvious ways even when it appears to be working.

    5.2 The mathematical signal model, as implemented¶

    Two competing profiles are fit to every detected event (detect/model_comparison.py):

    Symmetric (symmetric_profile, the null hypothesis — describes a planet, an eclipsing binary, or a symmetric noise excursion equally well):

    flux(t) = baseline − depth · exp(−½((t − t0)/width)²)

    Parameters: t0 (time of minimum), depth, width (a single Gaussian σ shared by both sides), baseline.

    Comet (comet_profile — Gaussian ingress joined to an exponential egress at the minimum):

    flux(t) = baseline − depth · exp(−½((t − t0)/ingress_width)²)   for t ≤ t0
flux(t) = baseline − depth · exp(−(t − t0)/egress_tau)          for t > t0

    Parameters: t0, depth, ingress_width (σ), egress_tau (τ), baseline — one more free parameter than the symmetric model.

    Both are fit by bounded nonlinear least squares (scipy.optimize.least_squares, method "trf", up to 2000 function evaluations) over a window widened by padding_factor (default 1.5×) beyond the detected event window, specifically so the recovering tail — which by construction extends past the point where flux first returns within the detection threshold — is not truncated (compare_models docstring). Each fit is packaged as a ModelFit (core/types.py) carrying chi2, n_params, n_points, and a converged flag; ModelFit.bic computes chi2 + n_params · ln(n_points) (lower is better), with the n_params penalty specifically there to stop the comet model's extra free parameter from winning by flexibility alone (docstring: "The penalty term is what stops the extra free parameter of the comet profile from winning by flexibility alone").

    compare_models returns None — an explicit "not fit" outcome, not a fabricated number — when the padded window holds fewer than 8 cadences, too few to constrain the 5-parameter comet model.

    5.3 Shape parameters, by their real names in the code¶

    Symbol (science note / research log) Code name (ModelFit.params key) Meaning
    σ ingress_width (comet model) / width (symmetric model) Gaussian standard deviation of the falling side, days
    τ egress_tau E-folding timescale of the recovering side, days
    — depth Fractional flux loss at minimum
    — t0 Time of minimum
    — baseline Local out-of-dip flux level

    ModelComparison.tau_over_sigma (core/types.py) computes egress_tau / ingress_width directly from the fitted comet-model parameters, returning nan if either is non-finite or ingress_width ≤ 0.

    5.4 ΔBIC: the model-comparison ranking statistic¶

    ModelComparison.delta_bic (core/types.py) is BIC(symmetric) − BIC(comet); positive favours the comet profile. ModelComparison.favors_comet returns True when delta_bic exceeds a configured threshold (ScoringConfig.delta_bic_threshold, default 10.0 in config/thresholds.yaml — the conventional "strong evidence" cutoff per Kass & Raftery 1995, cited in research log 007's references). This threshold is a single source of truth: it is passed into ModelComparison at construction from ScoringConfig.delta_bic_threshold specifically "so there is one source of truth" between the ranking metric and the flagging decision (core/types.py comment on ModelComparison.delta_bic_threshold).

    5.5 τ/σ: why it matters, and what it alone cannot tell you¶

    ΔBIC answers "is this profile asymmetric relative to a symmetric model?" It does not answer "is the asymmetry pointed in the direction a trailing dust tail produces?" — a fast-fade/slow-recover event and its exact time-reversed mirror image (slow fade, fast recovery — a leading-tail or otherwise "backwards" geometry, unphysical for a trailing comet tail) are equally asymmetric relative to a symmetric model, so ΔBIC cannot distinguish them. Only τ/σ carries directional information: τ/σ > 1 means the fitted egress is longer than the fitted ingress — the trailing-tail signature; τ/σ < 1 means the reverse.

    This is not a hypothetical concern — it is a documented, resolved bug in this project's own history. Research log 007 (docs/research_log/007-delta-bic-is-direction-blind.md) constructed a synthetic mirror-image test: two events, identical in depth, noise, and total duration, differing only in which side was the long one.

    Trailing tail (comet-like) Leading tail (time-reversed)
    ingress / egress duration 2.4 h / 12.0 h 12.0 h / 2.4 h
    τ/σ 4.15 0.23
    ΔBIC 151 201 (higher)

    The physically backwards event scored a higher ΔBIC than the genuine comet-like event. On ΔBIC alone, the unphysical event would have been the more confident detection. This is why the actual flagging rule (detect/scoring.py, score_event) requires both conditions:

    flagged = (
    np.isfinite(delta_bic) and np.isfinite(tau_over_sigma)
    and delta_bic > cfg.delta_bic_threshold
    and tau_over_sigma > cfg.tau_over_sigma_threshold
)

    with ScoringConfig.tau_over_sigma_threshold defaulting to 1.0. Research log 007's explicit warning: "Do not 'simplify' this rule by dropping the τ/σ condition." Doing so would silently readmit every physically-backwards event the fix was written to exclude, without failing the six-dip validation gate (both real comet events and their hypothetical mirror images pass ΔBIC identically well) — the same failure mode as research log 003, arriving from a different direction (see §5.6).

    5.6 The half-depth comparison problem (research log 003)¶

    Before τ/σ existed as the primary shape statistic, this project's original discriminator was a contour-based duration asymmetry, A_dur = (T_egress − T_ingress) / (T_egress + T_ingress), with each side's duration measured from the half-depth crossing to the dip minimum (detect/asymmetry.py, measure_side / compute_asymmetry — this code and metric still exist and are still computed and reported, just no longer used to decide flagging; see below).

    The problem, found empirically 2026-09-13: running the detector on KIC 3542116 recovered all six published dips, but the measured A_dur values were inconsistent and mostly negative, even though Rappaport et al. (2018) describe every one of these events as having a steeper ingress and a longer egress — every value should have been positive.

    Three hypotheses were tested and eliminated (research log 003): baseline window too short (falsified — sweeping 101→1001 cadences moved A_dur by <0.02); detrending distorting the profile (falsified — raw and detrended flux gave identical values); sign convention inverted in code (falsified — synthetic injections with known ordering recovered the correct sign).

    The actual cause is mathematical, not a coding error. At depth fraction f, the Gaussian ingress side reaches the contour at T_ingress(f) = σ√(2 ln(1/f)) and the exponential egress side at T_egress(f) = τ ln(1/f). At the half-depth contour (f = 0.5) these become 1.177σ and 0.693τ respectively. Setting them equal gives the sign-change condition:

    τ/σ = 1.177 / 0.693 ≈ 1.70

    So any event with a genuinely longer tail in the range 1 < τ/σ < 1.70 — a real, physically comet-like event — produces a negative half-depth A_dur, the wrong sign, because the half-depth contour samples the compact, nearly-symmetric core of the profile, not the extended wing where the comet signature actually lives (core/types.py, ModelComparison.tau_over_sigma docstring, and research log 003 both state this explicitly). Confirming evidence: measuring A_dur at successively deeper contours (50% → 25% → 12.5% depth) moved every one of the six dips monotonically toward positive, exactly as this explanation predicts (research log 003's table).

    Resolution: ModelComparison.tau_over_sigma, derived from the whole fitted profile rather than a single depth-fraction level set, became the primary shape statistic, with ΔBIC as the primary ranking metric (§5.4–5.5). A_dur (and its bootstrap significance, EventScore.a_dur_sigma/significance) is retained in EventScore and CandidateRecord.to_row() as a reported, interpretable cross-check — but per detect/scoring.py's own docstring, it "no longer decide[s]" whether an event is flagged.

    Wider lesson, stated directly in the research log and worth repeating here: the pipeline recovered 6/6 published epochs while its central discriminator carried the wrong sign. Recovering known events at the right time is necessary but not sufficient — it says nothing about whether the shape statistic driving a classification decision is even pointed the right direction. This is why this project treats "passes the validation gate" and "the discriminating statistic is trustworthy" as two separate claims, each requiring its own evidence (research logs 003 and 007 are the record of that evidence for the statistics currently in use).

    5.7 The full decision sequence (README, detect/comet_detector.py)¶

    1. Detrend — remove instrumental drift (detrend/detrend.py; see 07_data_architecture.md).
    2. Find candidates — flag runs of cadences ≥4σ (config: CandidateConfig.sigma_threshold) below a rolling-median baseline using a robust MAD-based noise estimate (detect/candidates.py, detect/baseline.py).
    3. Measure shape — locate the interpolated minimum, measure ingress/egress duration and slope at the half-depth crossing (detect/asymmetry.py).
    4. Fit and compare models — symmetric vs. comet profile, ranked by ΔBIC (§5.2–5.4).
    5. Quantify uncertainty — bootstrap A_dur by perturbing in-event flux within its error bars and re-measuring (detect/scoring.py, bootstrap_a_dur_sigma, default 1000 draws).
    6. Flag — delta_bic > threshold AND tau_over_sigma > threshold (§5.5).
    7. Vet — PLANNED/NOT IMPLEMENTED. vetting/__init__.py is currently empty; no automated cross-check against variable-star/eclipsing-binary catalogues, flare morphology, or cross-target artefact detection exists in code yet, despite being described in the README's own numbered list of pipeline steps. See 06_data_sources.md §6.4 and Next Steps item D2.

    A periodicity check (detect/scoring.py, periodicity_flag, Lomb-Scargle via astropy.timeseries) is also computed per light curve and reported on EventScore.periodic/period_days, used as a ranking penalty, "never as a hard rejection" (docstring) — i.e. it does not gate flagged.
