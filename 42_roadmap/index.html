    42. Roadmap¶

    Status: reflects repo state as of 2026-09-16, commit 01c2051. This is a condensed, CURRENT-STATE snapshot of Next Steps.md PARTS D through J. It is a pointer, not a replacement — Next Steps.md is the live tracker and should be read directly for full detail, next-session priorities, and anything that has changed since this document was written. Every item below is stated as PLANNED or NOT IMPLEMENTED as the source document itself states it; nothing here is upgraded or downgraded in status relative to that source.

    42.1 PART D — Making results defensible (🟠 important, all PLANNED / NOT IMPLEMENTED)¶

    Item Status
    D1. False-positive laboratory (flare, EB, starspot, δ Scuti, momentum-dump, sector-edge-ramp lookalikes as documented negative classes with a confusion matrix) PARTIAL — flare and starspot classes exist in the classifier training generator (C1); eclipsing binary, δ Scuti, momentum dump, and sector-edge ramp classes are NOT IMPLEMENTED, and no confusion matrix of any kind exists (see 31_machine_learning.md §31.3)
    D2. Vetting module (src/exocomet/vetting/: catalog cross-matching, flare/periodicity/cross-target-artifact/data-gap/odd-even checks) NOT IMPLEMENTED — the directory is empty (see 28_limitations.md §28.4)
    D3. Blind-search protocol (tune on dev set, freeze + tag config, run once on search targets) PLANNED, NOT IMPLEMENTED as a formal followed process (see 36_research_integrity.md §36.3)
    D4. Ablation study (recall/FPR with each pipeline component removed) NOT IMPLEMENTED
    D5. Trials factor / empirical false-alarm rate NOT IMPLEMENTED (see 28_limitations.md §28.3; sharpened by J2 below)

    42.2 PART E — Engineering (🟢 later/polish)¶

    Item Status
    E1. pipeline.py (run_target() orchestrator with per-target error isolation) NOT IMPLEMENTED as a standalone module — the equivalent sequencing exists inline in cli.py and scripts/ingest.py, not as a reusable pipeline.py
    E2. cli.py subcommands (run, validate, inject) IMPLEMENTED — this is the one E-item actually done; see 35_code_reference/cli.md
    E3. Provenance manifest (results/runs/<timestamp>.json) NOT IMPLEMENTED (see 25_reproducibility.md §25.2 for the full gap analysis)
    E4. Memory-bounded batch processing (2-4 workers, not cpu_count()) NOT IMPLEMENTED
    E5. CI (ci.yml: ruff, mypy, pytest, ubuntu+macOS, 3.11/3.12, coverage) NOT IMPLEMENTED — .github/workflows/ contains ingest.yml, train.yml, survey.yml only; no CI-style lint/type/test-on-push workflow exists
    E6. Catalogue-driven target list + matched control group PARTIAL — scripts/build_target_list.py genuinely queries VizieR and matches to TIC (verified real: 505 rows from catalogue J/ApJS/225/15, 5/5 matched to TIC), but the matched-control-group logic returns zero matches for all 5 disc hosts, a real unfixed gap, and it is deliberately not wired into ingest.py's target sources
    E7. Benchmarks (tests/benchmarks/, runtime/memory vs light-curve length) NOT IMPLEMENTED — directory confirmed empty (see 27_testing.md §27.1)

    42.3 PART F — Science extensions (🟢 later)¶

    All six items (F1 cross-mission sensitivity comparison, F2 physical comet simulator, F3 independent second detector, F4 debris-disc-vs-control population comparison, F5 2-D depth×duration sensitivity map, F6 detrending-method comparison experiment) are NOT IMPLEMENTED. F2 (physical simulator) is separately named in PART I as the reviewers' single highest-priority training-data improvement; F4 is separately named as the part of the project most likely to produce a genuinely citable population-level result once a real candidate list exists.

    42.4 PART G — Release and publication (🟢 later)¶

    All six items are NOT IMPLEMENTED: CITATION.cff/CONTRIBUTING.md/CODE_OF_CONDUCT.md/SECURITY.md/CHANGELOG.md (G1 — confirmed absent by direct directory listing, 2026-09-16), a deployed MkDocs docs site (G2), Zenodo↔GitHub DOI integration (G3), a PyPI release workflow (G4), a JOSS-format paper (G5), and an external user successfully running the tool and filing an issue (G6).

    42.5 PART H — Later, agreed but parked (🟢)¶

    Item Status
    H1. AI review layer (skeptic, never decides, must allow insufficient_evidence) PLANNED, NOT IMPLEMENTED — see 36_research_integrity.md §36.1 for how its underlying principle is already reflected elsewhere
    H2. Website / dashboard PLANNED, NOT IMPLEMENTED — explicitly deferred by the project author
    H3. Claude Cloud routine for the search survey itself Confirmed impossible on this platform (Cloud routines cannot reach mast.stsci.edu at all — a platform egress policy, not a config gap). The daily-survey automation stays on GitHub Actions. A reporting-only Cloud routine (reads results, never fetches from MAST) is built and viable.
    H4. Second detector — technosignature/anomalous-dimming (Isolation Forest, KIC 8462852) PLANNED, NOT IMPLEMENTED — see 30_future_detectors.md
    H5. Learning pass (plain-language walkthrough of every module) Still owed, per the project's own tracker; this specification document is a step toward it but was not scoped as a replacement for it

    42.6 PART I — Future roadmap from external review (🟢, condensed to current-state pointers only)¶

    A detailed outside critique (2026-09-14) proposed a long list of longer-term direction. Its cheap, concrete risk-mitigation half was folded directly into the actual 2026-09-14 build (idempotent generation, per-cycle work caps, the written hold-out protocol, dedup/sanity checks, A2 provenance columns, a saved threshold artifact, skip-if-unchanged retraining, job isolation) and is reflected in the currently-built code described elsewhere in this specification. The bigger-picture half remains entirely unbuilt, in the reviewer's own rough priority order: a physical exocomet simulator (overlaps F2), a falsification engine (overlaps D1/D2), a full injection-recovery sensitivity map (overlaps F5), a formally frozen blind test set (overlaps D3), a detrending ensemble, a second independent detector (overlaps F3), a one-click per-candidate "case file," an AI skeptic with hard guardrails (overlaps H1), an "unknown-unknown" anomaly pass (bridges to H4), active learning, a human-in-the-loop review console, cross-mission/cross-sector confirmation, and population-level science (overlaps F4). None of these exist in code as of this commit.

    42.7 PART J — From the 2026-09-15 external reviews (🟢, condensed)¶

    Item Status
    J1. Pixel-level validation / TPF centroids NOT IMPLEMENTED — both reviews' top-ranked gap; see 28_limitations.md §28.4
    J2. Empirical look-elsewhere correction (N candidates per 10,000 null curves) NOT IMPLEMENTED — sharpens D5; feasible given ~0.8 s/star throughput, per the project's own reasoning, but not yet run
    J3. Sector-overlap test (TESS, n_independent_sectors column) NOT IMPLEMENTED — described as cheap given lc.meta already carries the sector list post-A2
    J4. Candidate JSON schema (one file per event, GitHub Pages explorer later) NOT IMPLEMENTED
    J5. Physical forward-model injector as a second injector class (alongside, not replacing, the existing parametric one) NOT IMPLEMENTED
    J6. β Pic as validation target #3 NOT IMPLEMENTED — noted as feasible given the SPOC-pinned loader already resolves β Pic to 10 clean products (A2 fix)
    J7. Bayesian candidate probability NOT IMPLEMENTED
    J8. Stellar-property-aware detection (radius, spectral type, age, disk/planet/binary knowledge) NOT IMPLEMENTED
    J9. Case-file / scientific report export (PDF+JSON+CSV) NOT IMPLEMENTED — overlaps E3
    J10. Live "stars currently being analysed" activity counter NOT IMPLEMENTED — explicitly gated on the six-event exam (see 31_machine_learning.md §31.3) being green first

    Rejected outright, recorded so they don't resurface: a static vanity-total dashboard, a weekly discovery digest (the reporting-only Cloud routine already covers this), and an invented 0–100 "Exocomet Priority Score" — explicitly rejected as manufacturing false precision the underlying numbers don't support, on the same principle this specification applies to the classifier's evaluation status in 31_machine_learning.md.

    42.8 Net picture¶

    The project's own tracker is consistent and has not been "improved" between logging and this document: PART A (correctness-blocking fixes) is done; C1/C2 (classifier data + training) are built with C2's backtest verification status genuinely uncertain (§31.2); C3/C4 (evaluation, wiring-in) have not started; and the overwhelming majority of PARTS D through J — the work that would make this project's results genuinely defensible to an outside reviewer, per PART I's own framing — remains PLANNED or NOT IMPLEMENTED. The single item both 2026-09-15 external reviews independently converged on as the most important missing capability, pixel-level vetting (J1), is unstarted.
